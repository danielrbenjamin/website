Problem

UBC Formula Electric is roughly 100 students across a dozen subteams, all editing CAD, firmware, and documentation that ultimately has to fit together into one car. That scale turns "keep everyone's files in sync" from a nicety into a real infrastructure problem — the kind that, left unsolved, costs the team actual rework every single build season.

SVNWORKS is the name I gave to the combined effort: hosting, version control, task tracking, and documentation, built and maintained so the team's process scales with its headcount instead of breaking under it.

SVN on Oracle Cloud

I set up and maintain a self-hosted SVN server on Oracle Cloud to host the team's CAD — SolidWorks assemblies across every subteam, organized into a folder structure that mirrors the car's own subsystem breakdown. SVN's check-out/check-in model, unlike a naive shared-drive setup, means two people can't silently overwrite each other's work on the same file, and every part carries a real version history.

Running it on Oracle Cloud rather than a spare laptop under someone's desk means the server's uptime doesn't depend on any one person's machine being on — a real risk for infrastructure a hundred-person team depends on daily.

Jira Milestone Tracking

Version control solves "whose file is this," but not "what's actually left to do before the car needs to run." For that, I set up Jira milestone tracking across subteams, giving leads a shared view of where each subsystem stands against the competition timeline instead of a dozen separate mental models of the schedule.

SOPs & Onboarding

A student team turns over roughly a third of its membership every year, which means undocumented process knowledge evaporates constantly. I wrote and maintain the SOPs and onboarding documentation for the CAD and infrastructure side of the team, so a new member's first week is spent learning the car, not reverse-engineering how the file server works from tribal knowledge.

Results

The team hasn't lost CAD work to file conflicts since the SVN setup went live, milestone visibility through Jira gives leads an actual read on schedule risk instead of a guess, and new members ramp up against written process instead of whoever happens to be in the shop that day. None of this is visible in a competition result, but it's the reason the visible work gets done on time.
